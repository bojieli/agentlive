# Paged reduction measurements

Measured locally on 2026-09-10 with Node 26.8.1 on macOS. These are single-process reducer/storage measurements, not end-to-end browser, terminal or server acceptance results.

Run after building the workspace:

```sh
node scripts/measure-paged-reduction.mjs 1000
```

The script accepts 1–500,000 events. It creates a private temporary TextStore, generates one message per 64 events (start, 62 text appends, completion), and writes 48 bytes per text append. Timestamps span eight simulated hours. It checkpoints every 256 events and at completion, opens the final checkpoint, and independently checks the first and last message text. It records reduction latency, content-operation timing, sampled heap/RSS, encoded blob bytes and file count. Reports are written under `probe-results`; temporary content is removed after a completed run. The measurement program uses a bounded latency histogram and samples process memory every 25 ms.

The retained results below include a completed final checkpoint and successful sampled-content checks. The 100-event report predates the histogram change and records latency percentiles from a sorted array of 100 samples; its memory sampling and workload are otherwise the same.

| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 100 | 7.250 s | 13.79 | 76.01 ms | 81.04 ms | 19,894,464 | 76,546,048 | 265,200 | 927 |
| 1,000 | 64.095 s | 15.60 | 62.03 ms | 76.09 ms | 30,394,616 | 100,352,000 | 3,785,369 | 8,133 |

Raw reports: [100 events](paged-reduction-100.json), [1,000 events](paged-reduction-1000.json).

The 1,000-event run spent 59.64 seconds inside `put`, 1.98 seconds inside `append`, and 2.03 seconds inside `read`. Total retained message text was 46,512 bytes, while encoded content occupied 3,785,369 bytes across 8,133 files. This includes immutable intermediate metadata/index versions and checkpoints; it does not imply all of those versions are needed by the final root.

Before directory-sync grouping, an initial timing pilot applied 100 events in 9.458 seconds (10.57 events/s, p95 104.96 ms), then failed in progress reporting because the script shadowed the storage variable. That pilot did not complete final checkpoint validation, so it is not included in the accepted result table. The corrected runs above completed validation. The timing comparison suggests improvement, but is not a repeated controlled benchmark.

The storage change retains file-data sync for each staged blob and performs one directory sync at the text operation boundary. The codec waits for that sync before returning a reference. Failed final syncs reject the operation; retries flush even already-installed content. Ordinary attachment installs and downloaded snapshot blobs retain their existing immediate directory-sync behavior.

These results do **not** satisfy the implementation plan's eight-hour/500,000-event seek target or its latency/memory acceptance matrix. The current benchmark covers message events only, excludes activity-index work and rendering, and does not measure cold seeking, browser IndexedDB, concurrent publishers/viewers or device lifecycle. Further work must reduce intermediate content growth, address file-count and write throughput, and measure the full workload with retained-root collection and real client behavior. The configured 512 MiB content quota remains a hard limit, not proof that a long recording fits.

## Bounded append batching

The second argument selects a reduction batch size (default 1, maximum 256):

```sh
node scripts/measure-paged-reduction.mjs 10000 256
```

Checkpoint reduction can combine adjacent appends to the same object and field. The implementation validates every original event's schema, sequence and timeline, then persists the combined derivative transition. It preserves stored event history, content addresses and final checkpoint identity; message/tool lifecycle events, field changes and object changes terminate a group. Interactive timed presentation still processes individual events. Production adoption covers server snapshot builds, browser receipt/historical seeks, terminal watch seeks and the skipped prefix of replay with `--from-ms`.

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1,000 | 256 | 3.051 s | 327.74 | 751.30 ms | 781.19 ms | 19,507,640 | 80,379,904 | 183,055 | 389 |
| 10,000 | 256 | 42.900 s | 233.10 | 1,133.51 ms | 1,260.39 ms | 43,011,928 | 130,072,576 | 4,872,819 | 5,367 |

Raw reports: [1,000 batched events](paged-reduction-1000-batched.json), [10,000 batched events](paged-reduction-10000-batched.json).

The 1,000-event batched run was approximately 21 times faster and used about 95% fewer encoded bytes/files than the individually reduced 1,000-event run. These are single local runs, not statistical guarantees. The larger run shows reduced throughput and growing metadata cost as the indexes expand. Batch percentiles measure an entire admitted batch and must not be presented as event or end-to-end display latency. The report now labels the latency unit explicitly and uses `reductionP50Ms`/`reductionP95Ms`.

The 500,000-event workload, cold seeking, activity-index/rendering costs, durable content collection and concurrent/device acceptance remain unverified. Batching removes many intermediate writes during reconstruction but does not collect existing unreachable content or improve individual-event live presentation by itself.

## Read-only retention diagnostics

`node scripts/measure-paged-reduction.mjs 1000 256 --retention` optionally traverses content references from the final checkpoint and from every generated checkpoint. This diagnostic reconstructs bounded JSON content, counts unique verified codec blobs and follows reference-shaped objects. It neither deletes files nor authorizes collection. Its generic JSON traversal is scoped to the synthetic fixture; production collection needs format-aware tracing, publication/read/export pins, safe retention policy and crash-safe reclamation. Diagnostic time is excluded from reduction timing.

A 1,000-event run stored 183,055 bytes in 389 blobs. The final checkpoint referenced 23,039 bytes in 74 blobs; all four retained checkpoints referenced 35,277 bytes in 92 blobs. Thus about 81% of stored bytes were outside the diagnostic's union of checkpoint references in this fixture. The read-only traversal completed in 42.7 ms. [Retained report](paged-retention-1000.json). A focused shared-reference fixture verifies unique counting, exclusion of an unreferenced write and unchanged storage usage/content. These counts support investigating unreachable intermediate versions; they are not a proof that deleting the difference is safe.

At 10,000 events, total storage was 4,872,819 bytes in 5,367 blobs. The final checkpoint referenced 165,914 bytes in 670 blobs; the union of all 40 checkpoints referenced 809,813 bytes in 1,128 blobs. About 83% of stored bytes were outside that union, while the final root alone accounted for about 3.4% of total bytes. Traversal took 494.9 ms. [Retained report](paged-retention-10000.json). Reduction took 70.130 seconds in this run with the larger performance process running concurrently; this is not a controlled throughput comparison with the earlier 42.900-second run. The deterministic total bytes/file counts match the prior fixture.

## 500,000-event quota failure

The original 500,000-event, batch-256 run terminated with `retry_later: Attachment capacity exceeded` from the shared blob-store quota. It completed 449,792 events before the next admitted reduction failed. Encoded storage reached 536,868,963 bytes of the 536,870,912-byte (512 MiB) limit, across 334,593 blobs. The quota was not increased or bypassed. Temporary content cleanup completed and the report was retained: [full failure report](paged-reduction-500000-quota-failure.json).

Reported elapsed reduction time was 4,455.103 seconds, with 100.96 completed events/s and a 2,629.83 ms batch p95. The run included a host pause and concurrent disk work, so its timing is not a controlled throughput baseline. Sampled peak heap was 42,225,496 bytes and RSS 144,654,336 bytes. These measurements cover the message-only reducer/storage workload, not rendering, activity indexing or arbitrary seeking. Since reduction failed, it did not reach final-checkpoint/sample-content validation and is not a successful 500,000-event acceptance result. The last failing batch may also have installed unreferenced intermediate content before quota rejection.

This establishes a concrete capacity failure below the target workload. The smaller retention diagnostics indicate a potential route through collection, but do not prove the projected retained footprint at 500,000 events or a safe collection design. Format-aware tracing, pinned roots, crash-safe reclamation and another complete long-session run remain required.

The retention diagnostic now delegates manifest/page discovery to TextContent.trace through the store API. That primitive validates every distinct codec page before returning a complete set and treats page text as opaque. Generic traversal of parsed application JSON is still diagnostic-only; this change does not turn the diagnostic into a garbage collector.

## Schema-aware reducer tracing

The benchmark's current --retention path now uses PagedReducer.trace plus codec tracing. It validates the checkpoint binding, index/map structure, object metadata and nested attachment-version/replacement maps, and follows only schema-defined content references. User JSON and attachment body hashes are not interpreted as internal content links. The earlier generic diagnostic is retained only for its isolated tests and historical comparison.

A fresh 1,000-event run reproduced the exact earlier byte counts: 183,055 total, 23,039 referenced by the final checkpoint, and 35,277 by all four checkpoints. Schema-aware traversal took 91.9 ms. Reduction without the large concurrent benchmark took 2.988 seconds; this remains a single local timing sample. [Typed-trace report](paged-retention-1000-typed.json). No collection is enabled: activity roots, root pins and crash-safe sweeping remain required for production use.

## Periodic collection pilot

Run `node scripts/measure-paged-reduction.mjs 10000 256 --collect --retention` to collect every 8,192 events and at completion, retaining the latest 128 generated reducer checkpoint roots. The 10,000-event pilot completed final checkpoint and sampled-content verification. Final storage was 809,813 bytes in 1,128 blobs, matching the independent schema-aware reference union, versus 4,872,819 bytes/5,367 blobs without collection. Two sweeps reclaimed 4,063,040 bytes in total. The 8,192-event sweep took 6.005 seconds and final sweep took 8.477 seconds. Total elapsed time, including collection, was 58.516 seconds; sampled peak heap/RSS was 43.2/133.8 MB. [Retained report](paged-reduction-10000-collected.json).

This reduces retained storage by about 83% for this fixture but adds 14.482 seconds of collection work. It is a single message-only local pilot, not the 500,000-event acceptance run. Trace work currently revisits shared checkpoint structures, so collection cost across 128 roots needs further measurement/optimization. Server automatic collection is still disabled pending remote-viewer and publication retention.

Real SIGKILL tests separately cover death during marking and after actual deletion begins. Reopen retains the marked text, reconstructs byte accounting from surviving files and discards abandoned mark databases under the exclusive store lock. These are process-termination checks, not machine-power-loss guarantees.

## Repeated-trace optimization

Collection now records fully validated codec traces in its attempt-local SQLite mark database. A repeated manifest reference can reuse those marks only after all its pages were verified and marked; retaining an exact raw blob does not establish a complete text trace. Conflicting descriptors abort marking. Scoped schema reads also use an attempt-local LRU cache limited to 128 ranges and 1,048,576 UTF-16 units, with cancellation checked on cache hits. Neither cache survives the collection attempt.

A 10,000-event run with codec trace memoization completed in 52.497 seconds. Collection took 4.013 seconds at 8,192 events and 5.581 seconds at completion, totaling 9.594 seconds versus the earlier pilot's 14.482 seconds. Final storage remained exactly 809,813 bytes in 1,128 blobs and matched the independent typed reference union. [Memoization report](paged-reduction-10000-collected-memo.json). This run started before the range-cache change; its result must not be attributed to that cache. Timings are single local samples, not controlled repeated comparisons.

A subsequent 1,000-event run with both optimizations completed in 3.107 seconds, including a 77.599 ms final collection. It retained 35,277 bytes in 92 blobs, matching the independent checkpoint union, and removed 297 blobs. Sampled peak heap/RSS was 20.10/81.72 MB. [Bounded-cache report](paged-reduction-1000-collected-cache.json).
